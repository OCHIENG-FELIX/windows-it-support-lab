# Windows IT Support & Troubleshooting Lab

## Project Overview

This project demonstrates practical IT Support and troubleshooting skills through documented Windows troubleshooting scenarios.

The objective is to develop and demonstrate a structured approach to identifying, diagnosing, resolving, and verifying common computer-related problems encountered in an IT support environment.

## Objectives

- Diagnose common Windows operating system issues.
- Investigate hardware and software performance problems.
- Troubleshoot network connectivity issues.
- Understand device drivers and system configurations.
- Apply structured troubleshooting methodologies.
- Document incidents, resolutions, and verification procedures.

## Technical Environment

- Operating System: Windows 11
- Command Line: Command Prompt and PowerShell
- System Tools: Task Manager, Device Manager, Event Viewer
- Networking Tools: ipconfig, ping, tracert, nslookup
- Documentation: Markdown and GitHub

## Practical Implementation Status

The documentation and practical exercises for this project have been developed and tested using a Windows 11 computer.

### Practical Exercises Completed

- Inspected Windows hardware and system configuration using System Information (`msinfo32`).
- Investigated memory consumption using Windows Task Manager.
- Identified resource-intensive applications and browser processes.
- Applied a practical memory-management recommendation by closing unnecessary browser tabs.
- Compared memory usage before and after troubleshooting.
- Inspected hardware devices and driver status using Device Manager.
- Identified an Intel Wi-Fi 6 AX200 wireless network adapter and inspected its driver information.
- Investigated DNS resolution and basic network connectivity using Windows diagnostic commands.

### Practical Findings

The system diagnostics exercise demonstrated that closing unnecessary browser tabs increased available physical memory from 1.13 GB to 1.9 GB.

Device Manager inspection showed no visible hardware or driver warnings, and Windows reported that the wireless network adapter was working properly.

A DNS investigation also demonstrated how to interpret DNS timeout warnings alongside successful name-resolution tests.

### Remaining Work

Some documented scenarios still require separate practical validation, including software installation troubleshooting and dedicated slow-computer investigations.

## Troubleshooting Methodology

Each exercise follows a structured troubleshooting process:

1. Identify the problem.
2. Gather information and observe symptoms.
3. Establish a probable cause.
4. Test possible solutions.
5. Implement the appropriate resolution.
6. Verify system functionality.
7. Document findings and preventive recommendations.
